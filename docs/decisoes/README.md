# Decisões arquiteturais

Registre aqui escolhas duradouras quando o motivo e as consequências precisarem sobreviver à conversa. Não é necessário criar uma decisão para cada mudança de código.

As decisões de capacidade e acesso permanecem em [requisitos de sessão](../requisitos-sessao.md), sem cópia aqui. Novos registros podem referenciá-las.

## Formato para próximas decisões

- **Título e data de registro.**
- **Situação:** proposta, aceita ou substituída. Não marcar aceita sem evidência de decisão.
- **Contexto:** necessidade e restrições concretas.
- **Decisão:** escolha e escopo.
- **Alternativas:** opções realmente consideradas; não inventar discussões anteriores.
- **Consequências:** benefícios, custos e limitações.
- **Referências:** requisito, implementação e evidências relevantes.

Ao substituir uma decisão, preservar o registro histórico e ligar os dois documentos. Uma proposta ainda não é uma regra para implementação.
